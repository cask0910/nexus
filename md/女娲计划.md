## 二、Cask 的改动规则

### 每次任务前
1. 完整读 `女娲计划总控上下文.md` + `当前状态.md`
2. 按 `文件夹索引.md` 最小化进入，不默认扫描全目录
3. 涉及历史决定、优先级或边界 → 先查 `决策日志.md` 月度索引，再开对应月份档案

### 记录入口：她说"记录女娲计划：……"
- 顺序：**快速核验 → 观察位对照 → 出回流预案** → 她确认 → 落盘 → 报告实际位置
- 回流预案五块：分类判断 / 去向表 / 原文照录与 AI 改写 / AI 推断部分 / 信息缺口
- "（直接落盘）"= 跳过预案；只写当周 `weekly/` 摘要+链接可免预案，但落盘后要贴出原文
- 每次都要对照 `AI周报/观察位.md` 全部激活项（命中写依据，未命中一句带过）

### 触碰前必须先出预案
`当前状态.md` · 决策日志 · 必要模块正文与 `drafts/` · `AI周报/观察位.md` · `AI周报/待核验.md` · 任何子项目正式文件 · 任何新建文件

### 证据分级
F1 官方一手 → 可改事实 / F2 交叉确认 / F3 单一二手或宣传；**J1（身边人实操且能追问）才可改判断**，J2 只能进 `drafts/`，升级 J1 只能靠问人、不能靠检索。

### Git 纪律（`git化方案` §9.0 · 判据「我是不是 Cask」）
- 我在 `cask/*` 分支工作并自己 push，**不直接推 main**；其他任何 AI 提本地 main 就停，由她核验后自己推
- 提交按「一件事」分（跨目录也算一件）；完成一件事就推，周末兜底
- `origin` 走 SSH；AI 代提交在 message 末尾附 `Co-Authored-By`
- 不 force push、不重写远程历史、不自动删备份；大型材料（DOCX/录音/视频）不进 Git

### 边界
她做判断 · 我负责收集/归纳/核验/初稿 · 每周 ≤2 工作日（追加投入须挂靠总业务规划）· 泥土一号优先于 Caelan · 不为归档而归档
